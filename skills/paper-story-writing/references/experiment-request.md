# 实验请求规范

当论文故事需要当前尚不存在的证据时，使用本规范。

论文写作 Agent 负责判断：

> 论文还需要什么证据，以及为什么需要。

实验执行 Agent 负责：

> 真正实现并运行实验。

不要混淆这两个角色。

## 核心原则

不要因为“多做几个实验总是更好”而提出实验请求。

每个新增实验都必须填补论文论证中的一个具体证据缺口。

提出实验前，应能够准确补全：

> 我们需要这个实验，因为如果没有它，关于 ______ 的主张 / 假说，
> 仍然缺少 ______ 的证据。

如果无法明确补全这句话，说明实验问题还没有定义清楚。

## 允许先检查已有材料

为了写出真正可执行、可比较的实验请求，论文写作 Agent 可以只读检查：

- 仓库结构；
- 现有实验代码；
- 配置文件；
- checkpoint；
- log；
- 已有结果；
- 表格；
- 现有论文内容；
- 已做过的 ablation。

这些检查用于理解现有实验体系、避免重复工作，并保证新实验能够与现有结果直接比较。

不要在论文写作任务中直接开始：

- training；
- evaluation；
- 大规模 sweep；
- 修改实验实现；
- 提交长时间运行任务。

## 实验请求必须说明什么

### 1. 实验目标

明确实验究竟要回答哪个科学问题。

不要只写：

> 对组件 X 做一个消融。

应该写清：

> 在其他组件和 evaluation 条件保持不变时移除 X，
> 检验归因于 X 的性能提升是否消失。

执行 Agent 应当知道：

> 这个实验到底要消除哪一个不确定性。

### 2. 在论文中的作用

明确这个实验服务于论文的哪一步论证。

例如：

- 支撑核心有效性主张；
- 验证某个机制；
- 排除替代解释；
- 建立某种 tradeoff；
- 证明某个设计选择合理；
- 强化与 baseline 的比较；
- 回答一个潜在审稿问题。

尽可能指出实验结果最终会强化：

- 哪个 claim；
- 哪一段论证；
- 哪张表；
- 哪张图；
- 哪一节。

### 3. 假说

如果存在明确预期，写出待检验假说。

例如：

> 预期假说 H1：……
>
> 竞争假说 H2：……

好的实验应尽量能够区分不同解释，而不只是再产生一个数字。

如果不同结果会支持不同故事，在运行实验之前就把这些可能性写清楚。

### 4. 实验比较关系

规定回答科学问题所需的最小比较。

明确：

- proposed method / treatment；
- control；
- 必要 baseline；
- 改变哪个变量；
- 哪些变量必须保持不变；
- 使用哪些模型；
- 使用哪些数据集；
- evaluation setting；
- 是否应复用现有 checkpoint 或配置。

尽量沿用论文现有实验体系，使新增结果能够直接比较，
避免引入无必要的 confound。

### 5. 指标

明确到底需要测什么。

每个 metric 都应该对应论文中的一个主张。

不要默认要求一大堆指标。

优先要求真正能够决定假说的测量。

### 6. 区分必要实验和扩展实验

明确分成：

#### 必须运行

回答当前问题所需的最小实验集合。

#### 高价值扩展

能够明显增强解释或论文说服力，但不是当前结论成立所必需的实验。

#### 可选探索

有兴趣、可能带来新发现，但不应该阻塞当前论文故事的实验。

不要把一个聚焦的证据问题无限扩张成大规模 sweep。

### 7. 预先规定不同结果意味着什么

实验运行前，应说明主要可能结果如何影响论文故事。

例如：

> 如果 A 明显优于 B：  
> 支持机制假说 H。

> 如果 A ≈ B：  
> 当前结果没有提供预期的区分性证据。检查这是因为假说不成立，
> 还是因为实验分辨率、方差或设计不足；据此决定是否弱化机制解释，
> 或设计新的诊断实验。

> 如果 A < B：  
> 应检查替代解释 D，并重新评估 claim C 是否还应该承担核心叙事职责。

目的不是提前猜中实验结果。

目的是确保这个实验无论得到什么结果，都能真正改变我们对论文论证的判断。

### 8. 返回内容

要求实验执行 Agent 返回足够完整的证据，包括：

- 精确实验配置；
- 必要的命令或配置标识；
- 原始或足够详细的数值结果；
- 比较所需的统计量；
- 可以直接进入表格的数值；
- 若需要画图，则返回 plot-ready 数据；
- 会影响解释的异常、失败或特殊现象；
- 对实验实际证明了什么的简洁事实性总结。

如果论文需要 figure 或 table，应在请求中明确指出。

### 9. 实现边界

论文写作 Agent 负责定义的是**科学契约**：

- 比较什么；
- 控制什么；
- 需要什么证据；
- 什么结果必须被返回。

不要无必要地规定：

- 具体代码结构；
- 函数怎么写；
- 文件怎么组织；
- execution agent 应该采用哪一种工程实现。

除非某个实现细节直接影响：

- 实验有效性；
- 可重复性；
- 与现有实验的可比性。

其余实现选择交给实验执行 Agent。

## 推荐输出格式

### 实验名称

一句话描述。

### 实验目标

准确说明要回答的问题。

### 论文作用

说明它服务于哪个 claim、机制或审稿问题。

### 假说

列出待区分的主要假说。

### 必要设置

模型、数据、baseline、control、变量和需要复用的已有条件。

### 指标

必须报告的 measurements。

### 必须运行

能够决定当前问题的最小实验。

### 高价值扩展

有明显增益但不阻塞核心判断的实验。

### 结果解释

不同主要 outcome 分别意味着什么。

### 交付物

执行 Agent 必须返回的结果、数据、图表材料和配置。

## Handoff

实验请求完成后停止。

不要在论文写作任务中自行开始 training、evaluation、sweep、代码修改或实验执行。

目标是输出一份：

> **可以直接交给实验执行 Agent、足以让其立即开始工作的实验任务说明。**
